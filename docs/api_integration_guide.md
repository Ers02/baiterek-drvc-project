# Инструкция по интеграции с API ДРВЦ (Общая шина)

## Общая информация

Данная инструкция предназначена для дочерних организаций (ДО), интегрируемых через **общую шину ДРВЦ**. Шина позволяет отправлять документы без индивидуальной настройки интеграции для каждой организации.

**Базовый URL:** `https://api.drvc.kz/api`

### Что такое общая шина?

Общая шина — это единый API-шлюз для всех дочерних организаций. Вместо отдельной интеграции с каждым банком, все ДО подключаются к одному endpoint'у ДРВЦ.

**Преимущества:**
- Единый формат данных для всех организаций
- Автоматическая группировка связанных документов (ПСД + смета)
- Централизованная обработка и назначение аналитиков

## Аутентификация

Все запросы к API требуют аутентификации через API-ключ, который выдаётся каждой дочерней организации.

### Получение API-ключа

1. Обратитесь к администратору системы ДРВЦ
2. Укажите наименование вашей организации
3. Получите уникальный API-ключ для доступа

### Передача API-ключа

API-ключ передаётся в заголовке `X-API-Key`:

```http
X-API-Key: your_api_key_here
```

## Endpoint: Загрузка документа

### URL
```
POST /external/upload
```

### Content-Type
```
multipart/form-data
```

### Заголовки
| Заголовок | Обязательный | Описание |
|-----------|--------------|----------|
| X-API-Key | Да | Ваш API-ключ |

### Параметры формы (Form Data)
| Параметр | Тип | Обязательный | Описание |
|----------|-----|:------------:|----------|
| file | File | ✅ | Файл документа (см. форматы ниже) |
| doc_type | String | ✅ | Тип: `PSD` (KENML/ZIP) или `SMETA` (Excel) |
| bank_name | String | ✅ | Наименование проекта/объекта |
| received_at | ISO 8601 DateTime | ✅ | Дата отправки (`2024-01-15T10:30:00`) |
| **external_id** | **String** | **✅** | **Номер документа в вашей АИС (критично для группировки)** |
| notes | String | ❌ | Примечания |

### ⚠️ ВАЖНО: Поле external_id

Поле `external_id` — **обязательно для интеграции через шину**. Оно используется для:
1. **Группировки документов** — если от одного проекта пришли отдельно ПСД и смета с одинаковым `external_id`, они объединятся в одну группу
2. **Назначения аналитика** — при назначении на один документ, аналитик автоматически назначается на все документы группы
3. **Сверки** — для поиска документов между вашей АИС и ДРВЦ

**Формат:** любая строка, уникальная в рамках вашей организации (например: `PRJ-2025-001`, `DOC-12345`)

### Данные отправителя (опционально)
| Параметр | Тип | Описание |
|----------|-----|----------|
| sender_first_name | String | Имя |
| sender_last_name | String | Фамилия |
| sender_patronymic | String | Отчество |
| sender_email | String | Email |
| sender_phone | String | Телефон |

### Callback (опционально)
| Параметр | Тип | Описание |
|----------|-----|----------|
| callback_url | String | URL для результата анализа |

## Примеры запросов

### cURL

```bash
curl -X POST "https://api.drvc.kz/api/external/upload" \
  -H "X-API-Key: your_api_key_here" \
  -F "file=@/path/to/your/document.kenml" \
  -F "doc_type=PSD" \
  -F "bank_name=Банк Развития - Проект Офис" \
  -F "received_at=2024-01-15T10:30:00" \
  -F "notes=ПСД на строительство адм. здания" \
  -F "sender_last_name=Иванов" \
  -F "sender_first_name=Петр" \
  -F "sender_email=ivanov@example.kz"
```

### Python (requests)

```python
import requests

url = "https://api.drvc.kz/api/external/upload"
headers = {
    "X-API-Key": "your_api_key_here"
}
data = {
    "doc_type": "PSD",
    "bank_name": "Банк Развития - Проект Офис",
    "received_at": "2024-01-15T10:30:00",
    "notes": "ПСД на строительство адм. здания",
    "sender_last_name": "Иванов",
    "sender_first_name": "Петр",
    "sender_email": "ivanov@example.kz"
}

with open("document.kenml", "rb") as f:
    files = {"file": f}
    response = requests.post(url, headers=headers, data=data, files=files)

print(response.json())
```

## Ответ API

### Успешный ответ (200 OK)

```json
{
  "id": 12345,
  "doc_type": "PSD",
  "bank_name": "Банк Развития - Проект Офис",
  "sender_first_name": "Петр",
  "sender_last_name": "Иванов",

  "notes": "ПСД на строительство адм. здания"
}
```

### Ошибки

| Код | Описание | Решение |
|-----|----------|---------|
| 401 | Неверный или отсутствующий API-ключ | Проверьте заголовок X-API-Key |
| 400 | Некорректные данные | Проверьте формат данных и обязательные поля |
| 422 | Ошибка валидации | Проверьте типы данных (например, формат даты) |
| 500 | Внутренняя ошибка сервера | Обратитесь к администратору |

### Пример ошибки (422)

```json
{
  "detail": [
    {
      "loc": ["body", "received_at"],
      "msg": "invalid datetime format",
      "type": "value_error.datetime"
    }
  ]
}
```

## Форматы файлов

### Тип PSD (Проектно-сметная документация)
| Расширение | Описание |
|------------|----------|
| `.kenml` | Файл ПСД в формате KENML |
| `.zip` | Архив с файлами `.kenml` внутри |

**Требования:**
- Макс. размер: 50 MB
- ZIP может содержать несколько .kenml файлов
- Должно соответствовать спецификации KENML

### Тип SMETA (Смета по шаблону ДРВЦ)
| Расширение | Описание |
|------------|----------|
| `.xlsx` | Excel-файл по шаблону ДРВЦ |

**Требования:**
- Строго по шаблону (скачать: `/api/plans/template/download`)
- Лист «Позиции для загрузки»
- Обязательные колонки: Код ЕНС ТРУ, Наименование, Количество, Цена

> ⚠️ **Несоответствие типа файла и doc_type приведёт к ошибке!**

## Статусы обработки

| Статус | Описание |
|--------|----------|
| `NEW` | Загружен, ожидает назначения |
| `PARSED` | Файл распарсен, позиции извлечены |
| `ASSIGNED_TO_ANALYST` | Назначен аналитику на анализ |
| `FOR_APPROVAL` | На утверждении у директора |
| `APPROVED` | Утверждён, формируется ответ |
| `COMPLETED` | Готов к отправке |
| `SENT` | Ответ отправлен вашей организации |
| `ERROR` | Ошибка при обработке |

## Группировка документов (ПСД + Смета)

Если у проекта есть и ПСД, и смета — загрузите их **с одинаковыми** `bank_name` и `external_id`:

```python
# Загрузка ПСД
requests.post(API_URL, data={
    "doc_type": "PSD",
    "bank_name": "Школа №15, Алматы",
    "external_id": "PRJ-2025-001",  # ← одинаковый ID
    ...
}, files={"file": psd_file})

# Загрузка сметы
requests.post(API_URL, data={
    "doc_type": "SMETA",
    "bank_name": "Школа №15, Алматы",
    "external_id": "PRJ-2025-001",  # ← тот же ID
    ...
}, files={"file": smeta_file})
```

**Результат:**
- Документы отображаются как одна группа
- При назначении аналитика на один документ — назначается на оба
- Сроки и дедлайны применяются ко всей группе

## Получение результата

### Вариант 1: Callback URL

Если при отправке указан `callback_url`, результат анализа будет отправлен POST-запросом на этот адрес с:
- `document_id` — ID документа в системе ДРВЦ
- `status` — статус обработки (`completed` или `error`)
- `file` — ZIP-архив с полным отчётом анализа

### Вариант 2: Проверка статуса

По договорённости с администратором можно получить статус по document_id через отдельный endpoint (уточняйте у администратора).

## Требования к наименованию проекта (bank_name)

Используйте **читаемое и уникальное** название проекта. Рекомендуемый формат:
```
[Тип объекта] [№/название], [город/регион]
```

**Хорошие примеры:**
- `Школа на 1200 мест, г. Алматы`
- `Адм. здание БРК, Нур-Султан`
- `Реконструкция дороги М-36, ВКО`
- `Филиал Народного Банка №15, Шымкент`

**Плохие примеры (избегайте):**
- ❌ `Проект` — неинформативно
- ❌ `12345` — только цифры
- ❌ `smeta_final_v2.zip` — имя файла

> 💡 **Совет:** `bank_name` + `external_id` = уникальный идентификатор проекта. При повторной загрузке с теми же значениями документы сгруппируются.

## Часто задаваемые вопросы

**В: Можно ли отправить смету вместо ПСД?**
О: Да, укажите `doc_type=SMETA`.

**В: Как узнать, что анализ завершён?**
О: Используйте callback_url или обратитесь к администратору для настройки уведомлений.

**В: Можно ли отправить несколько файлов одним запросом?**
О: Да, упакуйте их в ZIP-архив.

**В: Что делать при ошибке 413 (Payload Too Large)?**
О: Разделите данные на несколько файлов или уменьшите размер архива.
